# 图解动效设计规则

## 风格与画幅

先按 [styles.md](styles.md) 选四组方案之一，再选 preset；八个 preset 不是八套独立风格。横版为 1920×1080，竖版为 1080×1920，只构建登记支持的组合。

黑橙图解以深黑背景、浅字、橙色图解强调与绿色字幕关键词为主。横版图解居右、人物居左下；`black-orange` 竖版为右下 240×240 圆窗，`black-orange-center` 竖版为居中 468×568 圆角人物窗，两者横版相同。改画幅依照语义重排卡片，不裁切横版合成画面。

金框知识窗以顶部主题、人物/图解主窗、字幕和底部主题或身份信息组成竖屏。`green-gold` 使用经典 1056×594 横窗；`green-gold-portrait` 根据源比例取景：竖源使用 720×1280 高窗，其余使用横窗，并完整容纳源画面；`identity-blue` 使用蓝灰金框和人物介绍区。`presentation` 决定当前主窗显示人物还是图解，默认首个 `statement` 显示人物。

纸墨讲解使用浅纸底、墨色正文与衬线标题，人物不出镜，适合阅读讲解。横屏 PPT 使用标题、序号、对照块和大字结论，并保留左下人物小窗；`ppt-bright`、`ppt-calm` 是同组明亮与沉稳两套配色。两组均为横版，保持原声，当前输入格式仍要求提供 `presenter`。

## 文字与字体

正文使用本地 Noto Sans SC；纸墨与 PPT 标题同时使用 Noto Serif SC。构建器从锁定 npm 依赖复制文案所需 Unicode 字符分片及对应 OFL，不加载网络字体，不复制系统苹方、宋体。

标题建议不超过 22 个汉字、卡片标题 10 个、正文 18 个。先按含义拆页，不靠持续缩小字体塞满。`identity-blue` 上限为姓名 20 字、身份 28 字、最多三条简介且每条 30 字；接近上限也必须查看实际换行与字形。不同字体、标点和英文长度会影响容量。

## 六种版式

| 版式 | 适合表达 |
| --- | --- |
| `diagram` 图示 | 两个概念的结构关系；内置 `cube`、`plane` 是语义占位。 |
| `compare` 对照 | 两种条件、方案或状态。 |
| `flow` 流程 | 两步顺序或因果关系。 |
| `cards` 要点卡 | 1–4 个并列要点。 |
| `timeline` 前后变化 | 当前与之后的变化。 |
| `statement` 大字结论 | 一页一个清楚结论。 |

选版式依据当前口播，不沿用示例观点。图解保留条件和判断语气，不虚构数据。来源文字只来自用户提供的真实材料；`source_note` 不是自动检索、引证或事实核查功能。

## 动效与字幕

用短淡化、轻移或线条出现服务讲解节点，保持可定位的时间轴，不使用随机数、定时器或无穷循环。人物、图解和字幕互不遮挡。知识窗的 `host` 场景使用人物主窗，`graphic` 场景使用图解主窗，不改变场景时间。

字幕原文、分段、`start/end` 在所有风格间保持一致，到 `end` 关闭。`emphasis_words` 是可选关键词，具体显色依 preset；不要为强调改写原口播。输入原声保留，不自行配音、加音乐、音效或再次降噪。

## 实际画面验收

在最终 MP4 中检查全部版式、最长标题/正文/字幕、场景首尾与转场。图解边界检查通过仍需查看实际文字；真人窗口检查头顶、眼睛、嘴和下颌。圆窗/居中窗口会裁切源画面，完整取景可能带留白或让人物偏小，按真实素材确认。

检查成片声音与画面同步并逐字听审。匿名测试图形与提示音只验证技术链路，取帧不能替代全片连续视听；尚未完成的检查如实标明。
